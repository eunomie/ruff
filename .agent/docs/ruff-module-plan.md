# Ruff Dagger module (`.dang`) — implementation plan

## Goal
A Dagger module written in `.dang` that wraps the `ruff` Python linter/formatter,
exposing functions to lint and format a source directory. Root of `eunomie/ruff`
is simultaneously a **workspace** and the **module it exposes**, mirroring
`dagger/java-sdk`'s dual `dagger.toml` + `dagger-module.toml` root shape.

## Decision 1 — base container: direct-binary extraction, NOT uv/pip

`ruff` is a self-contained static Rust binary. `ghcr.io/astral-sh/ruff:<v>` is a
scratch-based image containing only `/ruff` (verified: 27 MB static binary, no
shell). Ruff operates directly on source files — it needs **no** Python, venv,
pip, or uv to run. It is never installed *into* a user's Python environment.

Therefore we reuse pytest's **general pattern** (pinned-Dockerfile binary
extraction via `dockerBuild.rootfs`, Alpine base, `withMountedCache` cache
volume, `withDirectory` to place the binary on PATH) but **not** the uv/pip
dependency machinery (`resolveRunner`/`uvResolve`/`installPytestOtel`). That
auto-detect/venv-fallback logic exists because `pytest_otel` must be installed
alongside the user's project inside their Python env; ruff has no such
requirement, so importing it would be dead complexity.

This mirrors exactly how pytest extracts the `uv` binary from
`ghcr.io/astral-sh/uv` — we extract `ruff` from `ghcr.io/astral-sh/ruff` the
same way (mirror-image pattern).

## Decision 2 — workspace/module TOML (generated by real engine at beta.6)

Scaffold with the real CLI at `--x-release=v1.0.0-beta.6`:
1. `dagger sdk install dang` → writes `[modules.dagger-dang-sdk]` +
   `[modules.dagger-dang-sdk.as-sdk] name = "dang"` into `dagger.toml`.
2. `dagger module init dang ruff --path .` → generates root `dagger-module.toml`
   (`name = "ruff"`, engineVersion, `[runtime] source = "dang"`) and records
   `[[modules.dagger-dang-sdk.as-sdk.modules]] path = "."`.

**The no-double-registration nuance (confirmed via `dagger module init --help`):**
> "When --path is the default (`.dagger/modules/<name>`), also installs the new
> module as `[modules.<name>]` so it's callable here. Custom paths skip the
> `[modules.<name>]` install."

Passing `--path .` (a custom path) makes the engine **skip** the `[modules.ruff]`
install. Result: the root module is referenced *only* via the dang SDK's
`as-sdk.modules` authoring list — exactly the java-sdk shape.

**Why no `[modules.ruff]`:** `[modules.<name>]` registers a module as a
*workspace member/dependency callable from here* (internal tooling — e.g.
java-sdk's `packager` at `.dagger/modules/packager`). The root module IS what the
repo exposes; it is associated with its dang runtime through the `as-sdk.modules`
entry. Adding `[modules.ruff] source = "."` would register the workspace root as
its own member — redundant and self-referential; the engine deliberately omits it
for custom paths.

## Decision 3 — `main.dang` function surface (mirrors pytest's shape)

```
type Ruff {
  let ruffBinary: Directory!   # images/ruff dockerBuild.rootfs
  let alpine: Container!       # images/alpine dockerBuild
  pub source: Directory!       # from ws at sourcePath
  pub args: [String!]! = []    # extra args passed through to ruff
  pub container: Container = null   # optional custom base

  new(ws, sourcePath = "/", args = [], container = null)

  let defaultBase: Container!   # alpine + RUFF_CACHE_DIR + mounted cache + ruff on PATH
  let base: Container!          # container ?? defaultBase
  let workContainer: Container! # base.withDirectory("/work", source).withWorkdir("/work")

  pub check: Void @check        # `ruff check`  — fails on violations (exit 1)
  pub formatCheck: Void @check  # `ruff format --check` — fails if unformatted
  pub lint: String!             # `ruff check` (ReturnType.ANY) → stdout report, non-failing
  pub fix: Directory!           # `ruff check --fix` (ANY) → returns modified /work
  pub format: Directory!        # `ruff format` → returns formatted /work
  pub version: String!          # `ruff --version`
}
```

- `@check`-tagged `check`/`formatCheck` mirror pytest's `test: Void @check`.
- `lint` returns the human-readable report without failing the pipeline
  (`expect: ReturnType.ANY`).
- `fix`/`format` return the mutated `Directory` so consumers can chain.

## Verification plan
1. Scaffold via real CLI at beta.6; confirm generated TOML shape.
2. Create a Python fixture `tests/fixtures/dirty.py` with an intentional lint
   violation (unused import) + a formatting violation.
3. Run `dagger check` / call `check`, `lint`, `format`, `formatCheck`, `fix` —
   prove the violation is caught (non-zero) and that `fix`/`format` clean it.
4. Confirm root `dagger.toml` has NO `[modules.ruff]` while the module still
   loads/resolves as the dang SDK's own module.
